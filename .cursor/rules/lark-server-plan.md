
# 🚀 多用户支持改进实施计划

## 📋 总体目标
解决当前 `server-lark.ts` 中多用户并发时的 LarkClient 共享问题，实现真正的用户级别隔离，确保每个用户的操作使用正确的凭据。

---

## 🎯 核心问题分析
1. **全局 LarkClient 共享**：所有用户共用一个 `globalLarkClient` 实例
2. **Token 覆盖**：后连接用户的 token 会覆盖先连接用户的 token
3. **上下文混乱**：用户A的操作可能使用用户B的凭据执行
4. **资源泄漏**：没有用户断开连接时的清理机制

---

## 📝 详细实施计划

### Phase 1: 架构设计和数据结构调整

#### Task 1.1: 重新设计用户会话管理架构
**目标**：建立用户级别的资源隔离机制

**步骤**：
1. **分析当前数据结构**
   - 梳理 `sseConnections` Map 的当前结构
   - 识别需要用户级别隔离的资源（LarkClient、会话上下文等）
   - 评估内存使用和性能影响

2. **设计新的数据结构**
   - 设计 `UserSession` 接口，包含用户ID、LarkClient实例、连接信息
   - 设计 `UserManager` 类，管理用户级别的资源
   - 设计连接到用户的映射关系

3. **制定资源生命周期策略**
   - 定义 LarkClient 实例的创建时机
   - 定义 LarkClient 实例的销毁条件
   - 设计用户无活跃连接时的资源清理策略

#### Task 1.2: 接口定义和类型系统
**目标**：建立清晰的类型定义和接口契约

**步骤**：
1. **定义核心接口**
   - `UserSession` 接口：包含用户ID、LarkClient、连接列表、最后活跃时间
   - `ConnectionInfo` 接口：包含会话ID、transport、响应对象、用户引用
   - `UserManager` 接口：用户管理器的公共方法

2. **扩展现有类型**
   - 扩展 Express Request 类型，添加用户会话引用
   - 完善用户认证信息的类型定义

3. **错误处理类型**
   - 定义用户相关的错误类型
   - 定义资源管理相关的错误类型

### Phase 2: 用户管理器实现

#### Task 2.1: 实现 UserManager 核心功能
**目标**：创建管理用户会话和资源的核心组件

**步骤**：
1. **用户注册和查找**
   - 实现根据用户ID获取或创建用户会话的方法
   - 实现用户存在性检查
   - 实现用户信息更新机制

2. **LarkClient 实例管理**
   - 实现为用户创建专属 LarkClient 实例的方法
   - 实现 LarkClient 的 token 更新机制
   - 实现 LarkClient 实例的销毁方法

3. **连接管理**
   - 实现向用户会话添加 SSE 连接的方法
   - 实现从用户会话移除连接的方法
   - 实现获取用户所有活跃连接的方法

#### Task 2.2: 实现资源清理机制
**目标**：确保用户断开连接时正确清理资源

**步骤**：
1. **连接计数和监控**
   - 实现连接数量统计
   - 实现连接状态监控
   - 实现最后活跃时间更新

2. **自动清理策略**
   - 实现用户无活跃连接时的延迟清理
   - 实现基于时间的过期用户清理
   - 实现内存压力时的强制清理

3. **优雅关闭机制**
   - 实现服务器关闭时的用户资源清理
   - 实现 LarkClient 的优雅关闭
   - 实现清理过程的错误处理

### Phase 3: 认证中间件改进

#### Task 3.1: 修改 authenticateToken 中间件
**目标**：集成用户管理器到认证流程

**步骤**：
1. **用户会话集成**
   - 在 token 验证成功后获取或创建用户会话
   - 将用户会话引用附加到请求对象
   - 更新用户的 LarkClient token

2. **错误处理增强**
   - 处理用户会话创建失败的情况
   - 处理 LarkClient 更新失败的情况
   - 提供更详细的错误信息

3. **性能优化**
   - 避免重复的用户查找
   - 缓存用户验证结果
   - 优化 token 更新频率

#### Task 3.2: 用户上下文传递
**目标**：确保用户上下文在整个请求处理链中可用

**步骤**：
1. **请求对象扩展**
   - 在 req.user 中添加用户会话引用
   - 添加获取用户专属 LarkClient 的便捷方法
   - 添加用户连接管理的辅助方法

2. **中间件链优化**
   - 确保用户上下文在所有后续中间件中可用
   - 优化用户信息的访问模式
   - 减少重复的用户查找操作

### Phase 4: SSE 连接处理改进

#### Task 4.1: 修改 handleSSEConnection 函数
**目标**：使用用户专属的 LarkClient 处理 SSE 连接

**步骤**：
1. **用户会话集成**
   - 从认证中间件获取用户会话
   - 使用用户专属的 LarkClient 而非全局实例
   - 将连接注册到用户会话中

2. **连接生命周期管理**
   - 在连接建立时注册到用户管理器
   - 在连接关闭时从用户管理器注销
   - 处理连接异常时的清理工作

3. **错误处理改进**
   - 处理用户会话不存在的情况
   - 处理 LarkClient 不可用的情况
   - 提供更好的错误反馈

#### Task 4.2: 修改 handlePostMessage 函数
**目标**：确保消息处理使用正确的用户上下文

**步骤**：
1. **用户上下文验证**
   - 验证消息发送者的身份
   - 确保会话ID与用户身份匹配
   - 防止跨用户的消息处理

2. **LarkClient 使用**
   - 使用消息发送者的专属 LarkClient
   - 确保 API 调用使用正确的用户凭据
   - 处理 LarkClient 不可用的情况

### Phase 5: 工具执行隔离

#### Task 5.1: 确保工具执行的用户隔离
**目标**：保证 MCP 工具执行时使用正确的用户凭据

**步骤**：
1. **上下文传递机制**

2. **工具注册和执行**

   - 确保工具执行时的用户隔离
   - 处理工具执行失败的用户级别回滚

#### Task 5.2: API 调用隔离验证

1. **调用链审查**

2. **测试用例设计**

## 🎯 成功标准

1. **功能验证**：多个用户可以同时连接，且互不干扰
2. **性能标准**：支持至少 100 个并发用户连接
3. **内存效率**：每个用户的内存开销不超过 10MB
4. **稳定性**：7天连续运行无内存泄漏
5. **可观测性**：完整的日志和监控覆盖
